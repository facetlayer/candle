# Bugs and gaps to fix before 1.0

Items are ordered by priority. Each has a repro, the relevant code, a suggested fix, and a "done when".

---

## 4. Processes can escape tracking entirely

**Priority: medium.**

Evidence: three `candle --monitor` processes and their heartbeat services from a sandboxed test run
(`CANDLE_DATABASE_DIR=/private/tmp/candle-novice-mZ5amk/db`) were still running more than 2 hours later.
That database had no rows for them, so `list-all`, `find-orphans` and `kill-all` could not see them.
The run had hit `Warning: Could not kill process …: Operation not permitted` during `restart`, and then
reported cleaning up the stale entry.

The current `kill_one_running_process` looks correct for `KillOutcome::Error`, and I couldn't reproduce
this outside the sandbox. So the path that dropped the rows is unknown. Candidates:

- `filter_alive_processes` deciding "dead" when a sandbox makes `kill(pid, 0)` fail with an error other than `EPERM`.
- `ProcessNotFound` from an empty tree walk when `pgrep` itself is blocked. `get_process_tree` always
  includes the root, but check that `kill` on the root returning `EPERM` is not treated as `ESRCH`.

Suggested fix, independent of the root cause: make the system-wide commands (`list-all`, `find-orphans`,
`kill-all`) also scan the OS for `candle --monitor` processes (`pgrep -f -- '--monitor'`, filtered to
executables named `candle`) that have no DB row. Report them as `untracked`, and let `kill-all` stop them.

Done when: a monitor whose DB row is deleted by hand shows up in `find-orphans` and is stopped by `kill-all`.

## 6. MCP tool surface gaps

**Priority: medium.** The MCP tool list is part of the 1.0 interface.

In `rust/src/mcp/mod.rs`:

- **No `WaitForLog` tool.** Readiness is the headline agent feature, and MCP-only clients can't do it.
- **Inconsistent parameter names:** `name` (StartService, GetLogs, KillService, RestartService) vs
  `serviceName` (ListPorts, OpenBrowser). Pick one.
- **`projectDir` exists only on GetLogs.** Either add it to every project-scoped tool or remove it.
- **`AddServerConfig`** doesn't match the CLI's `add-service`. `AddService` would.
- **GetLogs defaults to 200 lines; CLI `logs` defaults to 100.** Align them.

Update `docs/mcp-usage.md` and `docs-site/docs/mcp-integration.md` with any changes.

## 7. `enableStdin` is advertised but undocumented

**Priority: low.**

The unknown-key warning prints `known keys: name, shell, root, enableStdin`, but `enableStdin` isn't
mentioned in `docs/`, the README or docs-site. `--enable-stdin` is deliberately hidden from
`add-service --help` (see `rust/docs/architecture/testing.md`), and there is no user-facing way to send
stdin (only raw `stdin_messages` inserts). Either remove it from the warning's key list
(`KNOWN_SERVICE_KEYS` in `rust/src/config/validate.rs`) while keeping it accepted, or document it
along with a way to use it.

## 8. Smaller issues

- **`list-ports-all` can't tell worktrees apart.** Two `web` services from different worktrees are listed
  with no project column. Add PROJECT (or DIRECTORY, like `list-all`) to the table; `--json` should
  include `projectDir`.
- **`wait-for-log` timeout units:** `--timeout 2` fails with `Timed out after 2000ms`. Report seconds,
  in the same unit as the flag.
- **`list-all` with nothing running** prints `No services configured.` It should say `No running services.`
- **Output without a trailing newline** (e.g. a `Continue? [y/N]` prompt) never appears in `logs` while
  the service is running. Either flush partial lines after a short idle period (with a marker), or
  document it in `project-setup`.
- **ANSI escape codes** are stored and printed raw, including in `--json`. Consider stripping them in agent
  mode and `--json`, or adding `--strip-ansi`.
- **`candle list <crashed-transient>`** errors with `No service 'x' configured`, while `candle logs x`
  works. Suggest: `No running or configured service 'x'; its logs are available with 'candle logs x'`.
- **Help formatting:** in `start --help` / `restart --help` the `--project-dir <dir>` row is misaligned
  (`rust/src/cli/help.rs`). `ps` pads its last column with trailing spaces.
- **`Run 'candle logs' to see logs.`** is printed even when `start` launched nothing because every
  service was already running.

## 9. Docs gaps

- **`docs/agents-intro.md`:**
  - Add `wait-for-log`. It's the most important agent command, and it's missing.
  - Say that agent mode already runs `start` in the background, so `--bg` isn't needed. The Haiku test
    agent passed `--bg` on every call because it believed it was required.
  - Move the stray "See which ports…" line into the command list.
  - Point at `candle get-doc project-setup`.
- **`docs/mcp-usage.md`:** "the CLI detects agents and never blocks" overstates it, since `wait-for-log`
  blocks by design. Suggest "never waits for interactive input".
- **`docs/transient-processes.md`:** after "drops off the list", add "its logs stay available with
  `candle logs <name>`".
- **`docs/project-setup.md`:** show the worktree port pattern concretely, e.g.
  `"shell": "PORT=${PORT:-3000} npm run dev"` with `PORT=3001 candle restart web` in the second worktree.
- **README:**
  - Replace the Quick Start placeholders (`--root <optional root directory>`) with one concrete example.
  - Add a short "Non-goals" section (no crash restart, no dependency ordering, no boot persistence,
    no port assignment) so those read as decisions.
  - Expand the comparison to process-compose and overmind.
  - The README says Linux/macOS only but mentions `netstat` on Windows. Pick one.
